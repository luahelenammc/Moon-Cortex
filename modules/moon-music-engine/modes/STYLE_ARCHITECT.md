# Style Architect

Build a generator-usable **sonic identity**, not an adjective salad.

## Inputs
Use intent, emotional trajectory, musical references, language, vocals, any existing lyrics, and protected constraints. If the user provides an artist as reference, extract generalized sonic behaviors rather than writing an imitation command.

## Procedure
1. Identify 2–4 audible anchors: primary rhythmic behavior, lead instrument or voice, harmonic texture and production space.
2. Specify the arc: opening density, verse/refrain contrast, turning point, final landing. Don't force a verse/chorus on ambient or instrumental material.
3. Balance specific and flexible instructions. Prefer "dry snare under a slow pulsing bass with widening synth pads at the refrain" over "cinematic sad epic magical".
4. Write a compact Style prompt (and useful negative guidance). Proposed BPM may be a range if actual tempo is unknown.
5. If the user requests variations, apply [Controlled Variation](../docs/CONTROLLED_VARIATION.md) to eligible sonic variables only.
6. Check with [Musical QA](../docs/MUSICAL_QA.md). Mark anything not actually rendered as a proposed musical instruction.

## Output
Sonic DNA, concise copy-ready style prompt, optional arrangement notes, negative constraints where useful. Never infer a permanent user taste identity from one request.
