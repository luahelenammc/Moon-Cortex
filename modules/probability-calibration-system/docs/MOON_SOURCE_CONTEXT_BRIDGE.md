# Moon Source Context Bridge

**MSL profile:** 5.1-compatible Markdown-native bridge; optional source governance remains separate from module operation.

Moon Source is the public context-architecture body. The [Moon Source repository](https://github.com/luahelenammc/Moon-Source) governs source authority, provenance, freshness, transport, and related context operations. Moon Cortex owns this probability-calibration module and its domain contract.

## Optional use

Consult a current Moon Source method when a forecast depends on:

- reconciling several sources with different authority;
- checking provenance, date, or freshness;
- preserving a source snapshot and later readback;
- moving evidence across systems or people with different access and authority.

Only use methods and sources that are actually available and authorized. A pointer to Moon Source does not create a connector, install a runtime, grant access, or make stale facts current. Probability Calibration System remains operable without Moon Source.

## Keep the bodies distinct

- Moon Source Public owns reusable context and source-governance methods.
- Moon Cortex Public owns the reusable probability-calibration system and its domain behavior.
- The local user owns current records, forecasts, choices, and updates.

Route a candidate by what it does. A general source or context-governance method may belong to Moon Source. A reusable system for estimating and updating outcomes across a problem field belongs to Moon Cortex when it meets that body public boundary. Generalization alone does not decide the destination.

A local context procedure may support this module without becoming its semantic authority. The public module may call or point to an optional source-governance step, but it does not depend on private Moon Source material or hidden memory.

## Freshness and provenance

Carry the source, date checked, relevant excerpt or fact, and authority needed to interpret the claim. When the current state cannot be verified, mark it unknown or stale and provide a safe fallback. Do not let a probability estimate conceal missing or outdated input.

The recommended freshness fields are defined in the [canonical entry](../PROBABILITY_CALIBRATOR.md#freshness-fields).
