# 🌙 Moon Cortex · Social Support Navigation System

**A field-first architecture for turning fragmented social-support situations into smaller, safer and institutionally routable next steps.**

People rarely arrive at a support system with a clean service name, a complete document set or one isolated problem. They arrive with a function that is failing, a relationship carrying too much, a barrier nobody has translated, and several doors that may or may not belong to the right institution.

The **Social Support Navigation System** is the Moon Cortex module for reconstructing that field before choosing a resource. It maps functions, dependencies, barriers, support tracks, a first useful door, next-step owners and event-based checkpoints. It keeps the person’s choices central and routes legal, clinical, emergency and other regulated decisions to the appropriate human or institutional authority.

## What this module is

It is a public, model-agnostic architecture for AI-assisted organization and navigation of social-support problems. It can help a person or helper:

- describe what is happening in observable terms;
- distinguish the surface request from the function that must change;
- map informal dependencies and supporter load without demonizing relationships;
- identify material, temporal, technical, cognitive, relational and institutional barriers;
- choose a first useful door instead of producing an unranked directory;
- verify current resources by jurisdiction and official source when live tools are available;
- turn experience into a routable institutional request;
- assign ownership of each meaningful next step;
- review progress when an observable event occurs;
- produce a case-local note, resource pack or support handoff with bounded claims.

## What it is not

This module is not a government office, public defender, law practice, social-work service, case-management license, clinical service, emergency dispatch, eligibility authority or substitute decision-maker. It does not diagnose, determine disability, promise a benefit or vacancy, decide legal responsibility, guarantee institutional action or impersonate a regulated professional.

The name is deliberately neutral. The module was generalized from a private internal donor project whose name is retained only in provenance notes. That lineage does not turn this public package into a public authority or publish the donor’s cases.

## One-minute architecture

```text
person's real situation
        ↓
Moon Cortex · Social Support Navigation System
        ↓
case-field reconstruction
        ↓
function + dependency map
        ↓
barrier / passage map
        ↓
selected tracks + first useful door
        ↓
verified institutional navigation
        ↓
owners + event checkpoints
        ↓
case-local state / resource pack / support handoff
        ↓
legal, clinical, emergency or regulated-professional handoff when required
```

The central movement is:

> **surface problem → concentrated functions → barriers → missing supports → transition**

## Use flow

1. Give the AI the complete package, an extracted copy of it or an equivalent complete module surface.
2. State what you are trying to make possible, avoid or stabilize. The AI should ask only questions that can change routing.
3. Let the navigator separate facts, reports, evidence and unknowns before building a plan.
4. When the situation earns it, create a **Living Case State** with selected tracks, owners and checkpoints. Simple requests should remain simple.
5. Verify jurisdiction-specific resources close to the action. A resource is not current merely because it appears in a static example.
6. Return a bounded output: direct next step, case note, resource pack, support handoff or professional-boundary route.

The package travels whole; attention remains proportional. A person should not have to become the unpaid coordinator of the architecture in order to receive help from it.

## Public responsibility

The module’s responsibility is to make a fragmented support problem smaller and more navigable while preserving the person’s sovereignty. It does not own the person’s life, the source record, the institutional decision or the professional judgment required at the next door.

### Case-local sovereignty

The public package contains no live case state. A user, household or authorized support system may create a local state outside the package. That state remains locally owned and should preserve its own source pointers, privacy rules, decisions, open loops and continuity. The public module may help organize a projection of that state; it must not become the only place where the case can be resumed.

### Jurisdiction and localization

The core is jurisdiction-neutral. Programs, offices, eligibility rules, phone numbers, forms, deadlines, accessibility conditions and institutional titles must be localized and checked against current official sources before use. Country, state, municipality, territory, service area and the person’s actual access conditions can all change the correct first door.

## Evidence and test boundary

The module includes a synthetic reality test and fictional examples. These demonstrate whether the documented architecture can preserve routing, ownership, uncertainty, privacy and professional boundaries. They do not establish social-work efficacy, clinical validity, legal validity, institutional adoption, measured outcomes or universal access.
