# Case Architecture

The case architecture turns a fragmented support situation into a locally owned, resumable map. It is a method for deciding what matters next, not a mandatory questionnaire or a professional case-management record.

## Reconstruct the passage

Begin with:

```text
current state → desired state → functions that must change
→ barriers and missing keys → support tracks → first useful door
→ owners → event checkpoint
```

The surface request is often only the first visible edge:

- “I need a benefit” may mean food, rent, medication, transport or documentation;
- “I need someone else to help” may mean one supporter is carrying too many functions;
- “The service will not respond” may mean a wrong channel, missing protocol, unclear owner or formal dispute;
- “I cannot manage this” may mean a cognitive, temporal, technical, material or safety barrier rather than lack of effort.

Reframing should clarify the function without denying the person’s account.

## Authority layers

Keep these layers distinct:

| Layer | What it can establish |
|---|---|
| User or household report | What the person says is happening and what they need |
| Direct record or document | What the inspected source shows or states |
| Structured case state | A traceable working representation of the current passage |
| Institutional response | What the institution received, decided, redirected or left pending |
| Qualified professional or authority | Decisions reserved to that domain |

A structured summary does not become stronger evidence merely because it is repeated. Preserve `unknown`, `reported`, `needs source`, `disputed` and `needs review` when those states change the route.

## Function and Dependency Map

Use a compact map when informal support or multiple systems are involved:

```text
function:
current supporter or system:
frequency / material load:
risk if the function stops:
possible formal support:
first contact:
new owner:
event checkpoint:
```

Map the function performed by a person, not a verdict about the person. A family member, partner, friend or neighbor may remain an important relationship while some of the work moves elsewhere.

### Household-held functions

Several people can jointly form an overloaded support infrastructure. Measure the total household-held work, not only each individual’s task count. A household that becomes more efficient at carrying an institution’s missing coordination has not necessarily achieved a safe transition.

## Barrier and Passage Map

For the selected passage, record:

- state A and state B;
- one to three primary barriers;
- secondary barriers such as time, language, transport, internet, shame, fatigue, accessibility or fear;
- existing keys such as documents, contacts, consent, money, network or authority;
- missing keys that must be obtained, translated, delegated or formalized;
- qualitative traversability: `clear`, `constrained`, `blocked` or `unsafe`;
- the minimum crossing that changes the field.

The map is a routing lens. It is not a validated score, diagnosis, safeguarding scale or finding of institutional fault.

## Track registry

Select only tracks that materially change the passage. A local state may represent them as:

```text
track:
purpose:
status: active | waiting_on_owner | blocked | escalated | paused | resolved | closed
priority:
dependency:
next action:
owner:
checkpoint:
privacy audience:
claim ceiling:
```

Possible tracks include material security, care, healthcare access, disability-related support, housing, transport, documentation, education, work, protection, institutional review and legal-boundary routing.

Parallel tracks must still be staged. A case with ten tracks is not a justification for giving one exhausted person ten simultaneous assignments.

## First useful door

The first useful door is the route most likely to create real ownership with the fewest additional doors. Test whether it can hear the functional problem, triage or redirect it, create a record, operate in the right jurisdiction and fit the person’s access conditions.

“Look online,” “ask another department” or “find a lawyer” without an identifiable channel, owner and next event is not a transferred function.

## Living Case State gate

Create a **Living Case State** only when persistence earns its cost. Good reasons include:

- multiple active tracks;
- repeated institutional contacts;
- chronology, records or source pointers that matter;
- safety, privacy or legal-boundary complexity;
- need to resume across sessions or handoffs;
- risk that a fresh worker or AI would otherwise make the person retell the case.

Do not create one for every simple request. A small case can remain a short note or direct answer.

### Minimum useful state

```text
case identity or safe pseudonym:
purpose and desired transition:
current state:
facts:
reports:
evidence and source pointers:
unknowns / disputed points:
functions and dependencies:
barriers and keys:
selected tracks:
first useful door:
owners:
open loops:
event checkpoint:
privacy and permitted audience:
professional-boundary flags:
current mode: INTERNAL PROCESSING | ASSISTED HANDOFF
```

The identity field should be as minimal as the purpose allows. Sensitive detail belongs in the narrowest local source that needs it.

## Checkpoints and loop closure

At each observable event, record:

- what changed;
- what was attempted or received;
- who responded or failed to respond;
- what remains informal;
- who now owns the next step;
- what is blocked and why;
- whether the route remains safe;
- whether the track closes, pauses, escalates or returns to reconstruction.

After an external handoff returns a response, resume internal processing first. Reconcile the delta before asking the person to do more.

## Preservation and non-takeover

If a person already has a spreadsheet, folder, record system, stable IDs or source library, treat it as existing infrastructure. Add a bridge or thin case layer where needed. Do not overwrite or absorb the source system merely because the public module can describe it.

The public module can help create a local case state; it must not become an indispensable private memory service. A good state remains recoverable by the person or their chosen source system if the assisting AI disappears.
