# Windows 98 · Classic Desktop Subtheme

**System:** Moon Image Cortex · **Type:** Windows-era subtheme of [Web Retro Image Gen](../WEB_RETRO_IMAGE_GEN.md) · **Status:** active, conditional · **Parent authority:** [Visual Director](../../../VISUAL_DIRECTOR.md#first-use) · [Windows subtheme index](README.md)

**Renderer:** external and optional. This is a visual-direction contract, not a theme pack, Windows emulator, asset license or rendered screenshot.

## Component activation

Select **Web Retro Image Gen → Windows 98** for an original interface, fictional application, desktop scene, early web product or historical illustration whose intended visual period is **Windows 98 / 1998–2000**. Preserve the user's intended era, screen medium, exact text and use. This is **not** a Windows 95 catch-all: shared Classic-shell features do not license a careless mixture of operating-system versions.

## Visual grammar: functional geometry before nostalgia

| Dimension | Windows 98-oriented direction | Avoid |
|---|---|---|
| Desktop | Conventional left Start menu, flat-ish taskbar with rectangular open-window buttons and tray clock | XP rounded Start button, Vista orb, Windows 7 superbar |
| Window | Rectangular titlebars, compact borders, system menus and 3D beveled controls | Frosted glass, huge radius and modern web card chrome |
| Palette | Neutral grays and light client panels; dark or saturated rectangular titlebar accents when the chosen Classic settings support them | Saturated XP Luna blue-and-green styling as an automatic default |
| Controls | Raised/sunken control edges, square checkboxes, densely spaced dialog groups, underlined access keys | Mobile-sized touch controls and floating icon-only actions |
| Iconography | Low-resolution, palette-conscious system-era icon construction with coherent silhouettes | Vista photorealistic high-resolution icons or post-2010 flat glyphs |
| Browser / web | Fixed or table-led layout, native form widgets, small raster images and link-focused hierarchy when historically appropriate | Modern responsive SaaS cards and invented 1998 HTML5 interactions |
| Wallpaper | User-selected image, pattern or muted flat desktop color | Treating a brand-era wallpaper as mandatory |

Treat **Windows 98 Classic UI** and a **webpage seen inside its browser** as two distinct layers. Browser chrome is an application shell; the page's typography, link styles, fixed-width tables and content density have their own source-dependent constraints.

### Material and medium separation

A **native desktop screenshot** has crisp rectangular pixels, raster fonts and aligned window edges. It does not intrinsically exhibit phosphor scanlines, physical monitor curvature or camera noise. A **photograph of a late-1990s computer monitor** may include CRT reflections, moiré, softness and camera perspective, but only when its device and capture support those effects. A **period print advertisement** can instead use paper halftone, restrained typographic framing and original hardware illustration. State which medium the user wants before adding texture.

### Era parameters

`artifact_class` (desktop, application, website, promotional composition), `year_range`, `shell_vs_web_page`, `classic_colorway`, `native_screen_resolution_or_unknown`, `browser_frame_policy`, `text_exactness`, `capture_medium`, `brand_rights`.

Do not invent a particular Internet Explorer version, installed application, service-pack label, system error code or equipment brand unless the brief or a checked source establishes it.

## Procedure

1. Identify a real task: web portal, local computer utility, installer, Explorer-like window or historical illustration.
2. Fix the intended Windows 98 era and decide whether the shell is actually visible.
3. Lay out compact navigation, title, menu and task controls around the user's content, not around nostalgia decoration.
4. Select a coherent Classic palette and control grammar; reserve high contrast for titlebars and focus areas.
5. Use era-appropriate icon density and text size at the target frame without filling every gap with bevels.
6. For an original web page, distinguish browser frame from website content, with realistic table/link/form density.
7. Apply photo-of-monitor effects only if there is an actual photographed device.
8. Verify window controls, taskbar, textual correctness, readability and originality.

## Direction studies

**Original archive search utility:** “A fictional Windows 98-style archive search application with a rectangular blue titlebar, compact menu, inset list view, square toolbar buttons and beige-gray system surfaces. One primary text field and a readable file list. No XP Luna bubbles, glass effects or modern toolbar ribbon.”

**Community page as a screenshot:** “An original 1999 community repair forum with compact HTML-style links, a two-column table-led page and small images, shown inside a period-plausible classic browser frame. No copyrighted existing website layout and no CRT lens effects on the digital capture.”

**Photographed device:** “A real late-1990s CRT on an office desk displaying a generic Windows 98-style file manager; camera perspective and reflections belong to the physical monitor, not a screenshot.”

## QA and cross-era failure gates

- Is the window grammar square and compact, or has it drifted into XP's rounded Luna controls?
- Did Vista Aero translucent frames, Windows 7 superbar, Windows 10 tiles or modern browser tabs appear?
- Is the desktop shell separate from the imagined webpage, and is the medium actually a native screenshot or a camera photo?
- Are all names, dates, messages and logos provided, original or explicitly uncertain?
- If the end user requested a working site, are focus, link hierarchy and accessibility planned, not merely visually depicted?

**Output:** `direction_sheet`, `specific_prompt`, optional `asset_spec` or `QA_report`. If no image renderer was invoked, state **not rendered**.

## Documentary reference
