# Moon Music Engine

Read `references/MUSIC_DIRECTOR.md` first. It is the canonical route and first-use authority. Consult only the needed method files in `references/modes/` and `references/docs/`; the complete public module snapshot travels under `references/`. Current source: https://github.com/luahelenammc/Moon-Cortex/tree/main/modules/moon-music-engine. This skill is documentation and routing, not an audio generator, a Suno plugin or permission to access accounts.

## Procedure

1. Identify whether the user wants musical taste mapping, discovery, real-reference distillation, original songwriting, lyric preservation or generator repair. Reconstruct only task-relevant sources, constraints and desired output; do not require a long questionnaire.
2. For `map my music taste`, `build my musical DNA`, `update my profile`, `discover for my taste`, automatically select Taste Cartographer (`references/modes/TASTE_CARTOGRAPHER.md`) and its schema. Work from user-volunteered and rights-permitted observations, not Spotify Platform/Content ingestion or streaming scraping. Preserve conditions, dislike nuance, fatigue, evidence levels and user-owned state. When a real song or artist is supplied **to design an original sound** as inspiration, **automatically select Reference-to-Feature Translator** (`references/modes/REFERENCE_TO_FEATURE_TRANSLATOR.md`) as the first primary motor. Name the sources in an analysis feature map, separate observed/sourced/user-reported/inferred traits and select an original sonic combination. Otherwise choose Style Architect, Lyric Doctor, Song Prototyper or Generator Debugger according to the task. Invoke controlled variation only when useful or requested.
3. Preserve user-supplied lyric by default and translate mood or references into concrete sound, pulse, instrumentation, vocal behavior and production choices. Never invent that you listened to a recording. Do not copy hooks, riffs, melodies, lyrics, recordings or distinctive close arrangements; removing names alone is insufficient.
4. If the user requests **music influenced by their profile**, read only a profile actually supplied or legitimately accessible and use `references/docs/PROFILE_TO_CREATION_BRIDGE.md` for consent-gated minimal sonic features. Without an authorized profile, never invent one. Provide a concise copy-ready **original** style prompt (without named artist/song references by default), structured lyrics only if warranted, specific negative guidance and suitable titles for new songs. When named references are used, retain a separate reference/feature/provenance map for clarity.
5. Express variation percentages as exploratory controls, not mathematical probabilities or verified acoustic distances. Claim seeded reproducibility only with a real implemented seeded algorithm.
6. Mark what was prepared, generated, actually heard or merely reported. State explicitly whether a Taste State was only proposed or actually saved; require authorization and working storage before writeback. Follow `references/docs/TASTE_PRIVACY_AND_PLATFORMS.md` and never ingest Spotify Platform/Content to build an AI-derived taste profile. For real results, make targeted corrections rather than assuming output quality from the text prompt.
