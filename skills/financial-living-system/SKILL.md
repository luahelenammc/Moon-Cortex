# Financial Living System

Read `references/ADAPTIVE_FINANCE_BOOTSTRAP.md` before substantive work. The complete module is bundled in `references/`; consult its companion documents by need. The live authority is https://github.com/luahelenammc/Moon-Cortex/tree/main/modules/financial-living-system. The bundle is a snapshot: compare the current public source when freshness or a changed method matters. Verify current external rules with relevant authoritative sources. Work in the user's language.

## Procedure

1. Resolve whether the user wants explanation, audit, setup or execution; honor a read-only request. Inspect authorized existing material before requesting repeated information. Preserve what already works.
2. Reconstruct financial friction, relevant jurisdictions, income and cash timing, credit and debt, obligations, shared money, reserves, the user's safety preferences and host capabilities. Label observations, reports, calculations, inferences and unresolved gaps separately. Ask only questions that change a route or safety decision.
3. Build the Financial Field Model and map the user's terms to a local lexicon. Select only capabilities the field warrants. Choose a proportional host profile: full living workspace, compact, single source, or integration with an existing system. Produce the smallest useful local form, not a fixed template.
4. Preserve the accounting distinctions: a credit purchase creates liability rather than immediate cash outflow; payment settles liability and is not a second expense; internal transfers are not spending; unreceived reimbursement is not cash; protected reserves are not free cash. Do not invent a balancing entry. Reconcile and expose residual differences.
5. Run the applicable `references/docs/FINANCIAL_REALITY_TEST.md`. Explain the capability plan, host, update responsibilities, validation and actual setup/installation state. Read back authorized mutations. Claim installation only with evidence. The Moon Source bridge is optional; say whether it was actually consulted.

Do not ask for passwords, PINs, CVVs, private keys, tokens or unnecessary account identifiers; minimize and protect third-party data. Verify current financial and legal facts when they materially affect decisions. Do not claim a bank connection, transaction, guaranteed outcome or professional authority from this method. If the host cannot persist or mutate, deliver a bounded installation-ready result with clear limitations.
